# PWAの更新

通常の画面・機能の更新に、アンインストールと再インストールは不要です。新しいビルドを公開すると、起動時・アプリに戻ったとき・オンライン復帰時に更新を確認します。新版が準備できたら「更新する」を選んで適用できます。「あとで」を選ぶとそのまま使えます。

写真登録・展示作成・タグ編集・並べ替え・保存の途中では、更新による再読み込みを保留します。保存するか編集画面を離れてから更新してください。別のタブで更新を適用しても、入力中のタブを勝手に再読み込みしません。

## 旧版からの初回移行

古い`tenugui-v1`はトップページ自体をキャッシュしていたため、新しい更新ボタンが届かない場合があります。保存を済ませ、このサイトのブラウザタブとホーム画面アプリをすべて閉じ、オンラインで開き直してください。初回のダウンロードが終わってから、もう一度すべて閉じて開く必要がある場合もあります。待機中の新版が有効になり、古いページのキャッシュが片づけられます。

## ホーム画面のアイコン

旧版の花柄を残し、画面に合わせて苔色・生成り・芥子色へ調整しています。マニフェストの画像URLには`?v=hanagara-2`を付け、同じ画像URLの古いキャッシュを避けています。アプリのID・起動URL・マニフェストURLは既存アプリと一致するように保ちます。

インストール済みのアイコンの更新はOS・ブラウザが管理します。Chrome 144以降では、アイコンURLの変更で更新を検知し、変更内容によってアプリのメニューから「Review app update」で確認できます。OS・ブラウザによって反映時期や手順は異なり、アプリ内の「更新する」だけでホーム画面のアイコンまで即時に切り替わる保証はありません。[Chromeの更新仕様](https://developer.chrome.com/blog/improvements-to-web-app-updates)

iOS向けには180pxの`apple-touch-icon`も用意しています。Safariではこの指定がマニフェストのアイコンより優先されます。既存のホーム画面アイコンが変わらない場合は、表示を変えるためにホーム画面への追加し直しが必要になることがあります。[MDNのアイコン解説](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Tutorials/CycleTracker/Manifest_file)

## 実装と再生成

`public/sw.js`の配信URLは固定です。ビルド時に配信内容へ版を埋め込むため、画面のコードだけを変更した更新も検知できます。新しいworkerは待機し、利用者が更新を選んだときに適用します。開発モードではworkerを登録せず、PWA更新の確認には本番ビルドを使います。[Service Workerのライフサイクル](https://web.dev/articles/service-worker-lifecycle)

ハッシュ付きのJS/CSSはキャッシュを再利用し、同じ名前のアイコン・マニフェスト等はネットワークで更新します。認証・API・動的ページ・アップロード写真はService Workerに保存しません。削除するキャッシュは`tenugui-`で始まるものだけです。

```sh
npm run icons
npm test
npm run typecheck
npm run build
```

アイコンを再度変更したときは、マニフェスト・HTMLのアイコン参照の版も更新してください。マニフェストの独自`version`フィールドだけを変更しても、更新の仕組みにはなりません。
